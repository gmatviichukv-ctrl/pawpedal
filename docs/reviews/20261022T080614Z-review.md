- **R3:** All errors are collected together. 30 days passes and 31 days fails. The past-date check compares strings, and `today` is passed in. Dog weight is required only when gear is booked. Duplicate gear is rejected. `2026-02-30` is rejected.
- **R4:** The overlap check is inclusive. Only active bookings block, and gear is checked against `>= stock`.
- **R4.5:** The check and the save run inside one serialized `transact` queue. The test fires two simultaneous requests and expects `[201, 409]` and exactly one saved booking. It does not exercise two separate server processes.
- **R5.3:** The email is required, and a missing email, wrong email and unknown ref return an identical 404 body. Ref and email matching are case-insensitive, and the tests assert identical bodies.
- **R5.4:** Cancel gives the same 404 for a wrong email and an unknown ref. Cancelling twice returns 409, and cancelling after `to` returns 409. Cancelling mid-rental is allowed, and the test uses a mocked clock to prove it.
- **R5.2:** Malformed JSON gives 400 through `.catch(() => null)`, never 500.
- **AGENTS.md:** `lib/` has no clock reads, Next imports or `fs`. Routes are thin, and persistence goes only through `server/store.ts`. Errors are `{ code, message }`. The store writes a temp file and renames it. Refs use `crypto.randomInt`.
